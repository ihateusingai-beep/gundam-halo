### Feature surface

| Feature | How |
|---|---|
| **Toggle** | `Cmd+K` / `Ctrl+K` global keyboard listener. Also click-outside on backdrop, `Esc`, or `Backspace` to clear query. |
| **Search** | Substring match on title / subtitle / keywords. Title-prefix gets the highest score (100+), exact-substring next (50), subtitle (20), keyword (10), multi-word AND fallback (5). No external fuzzy lib. |
| **Keyboard nav** | `↑` / `↓` move active item, `Enter` runs it, `Esc` closes, `Tab` cycles category filter (All → Navigation → Projects → Themes → Mac Control → System → All). |
| **Categories** | 5 fixed categories; each command is tagged. Group headers render in result list. |
| **Static commands** | Navigation (Overview / New / Settings), System (Refresh / Health / Gauges), Themes (8 themes + OFF), Mac Control (Clipboard / System Info). |
| **Dynamic commands** | One "Open project: <name>" and one "View memory: <name>" per project in `useProjectsStore`. Updates live as projects load. |
| **Recents** | localStorage-backed ring of the last 5 commands run. Renders at top of the result list when query is empty. |
| **Theme integration** | Theme switch commands go through `useThemeStore.setTheme`, which re-applies `[data-theme]` on `<html>`. Live-verified: switching to GOD changes every accent (frame corners, buttons, gauges) instantly. The palette border itself follows the active theme (cyan in NT-D, orange in GOD). |
| **Theme-active badge** | The currently active theme command shows `(active)` in its subtitle, so users can see at a glance what's running. |
| **Scoring on description** | NT-D shows "Unicorn psychoframe (active)" subtitle, so even when filtering by `theme`, users see the active state. |

### Command count

17 total at first paint (3 nav + 3 system + 9 themes + 2 mac control +
0 projects — backend not running). Scales linearly with project count.

### Code structure

- **`Command` type** — `{ id, title, subtitle, category, keywords, icon, perform }`.
  Single source of truth. `useCommands()` is a `useMemo` over the
  union of static + dynamic commands.
- **`openPalette()` / `closePalette()`** — module-level event bus
  (Set of listeners). Any component can call `openPalette({ category, initialQuery })`
  to deep-link into the palette with a filter / search already
  populated. Useful for "Tauri menu → switch theme" or "right-click
  on a project card → search for it".
- **`scoreCommand()`** — pure function, easy to swap for fuse.js
  later if the command count grows past ~50.
- **`runCommand()`** — wraps `cmd.perform()` in try/catch, pushes
  the id to recents, closes the panel, surfaces failures as Sonner
  toasts.

### State management decisions

- **No zustand store** for `open` / `query` / `active` — these are
  pure render-level UI state. A module-level listener Set is
  enough for the open/close bus.
- **Recents use `useState<string[]>`, not a re-render trick.**
  Earlier draft used a `recentsTick` counter to force re-reads
  from localStorage after `runCommand`. That's an anti-pattern
  (stale data on first render). Switched to direct state updates
  — recents reflect what's actually in storage.

## Design notes

### Why a module-level event bus, not zustand

`useThemeStore` and `useProjectsStore` are global because their
state has cross-component reach (every themed component reads
`--accent`, every page reads projects). The palette's `open` flag
is different — it's set by one component (the keyboard handler in
the palette itself) and read by one component (the same palette).
The `openPalette()` API is for *external* callers, but the count
of external callers is ≤ 3 (a future Tauri menu bar, a keyboard
shortcut help dialog, a "search" button somewhere). A `Set<fn>`
is the right size for that.

If we ever have 5+ external callers, we promote to zustand. Not
before — premature store promotion is the kind of thing that
makes a 200-line palette become a 500-line palette.

### Why fuzzy match is inlined

The standard move is `npm install fuse.js`. We didn't because:
- 17 commands. A linear scan with score numbers is fine.
- The scoring is bespoke (title-prefix > title-substring > subtitle >
  keyword > multi-word AND). fuse.js would either approximate this
  or fight us.
- We avoid a 5-10 kB dependency for 50 lines of code.

When the command count hits ~50 we revisit.

### Why palette state is `useState`, not `useRef`

`open` affects what renders (the whole panel). `query` affects
the filter. `active` affects the highlighted row. All three are
UI state, not refs. React's render loop drives the whole thing.

### Why a separate `CommandPalette` component, not inlined in `App.tsx`

`App.tsx` is the routing surface — adding 370 lines of palette
code to it would bury the routes. Components are cheap; route
files should stay navigable.

## Deferred / future work (not in B6 scope)

- **Search highlighting** — currently no `<mark>` inside the
  matching text. Low value at 17 commands; trivial to add when
  the count grows.
- **Icons via `lucide-react`** — we use Unicode glyphs (▣, ⌘, ↵).
  Looks great in the Gundam mono aesthetic; if we ever need richer
  icons, swap in lucide (already used elsewhere in the app).
- **Command history (text-input sense)** — we track which commands
  you ran (recents), not what you typed. Different feature.
  Punt to "smart suggestions" sprint.
- **Tauri menu bar integration** — `openPalette({ category: "Themes" })`
  from a native menu item would be a clean one-liner. Punt to M11.
- **In-palette file picker for "Read file"** — we have a
  `mac.read-clipboard` and `mac.system-info` command but no
  `mac.read-file` yet. The backend endpoint exists. Add when
  the file browser is needed.
- **Fuzzy match library** — see "Why fuzzy match is inlined" above.
- **Tauri-only shortcut hint** — `⌘K` works on web. On Tauri
  the convention is `Cmd+K` too, but a separate `Cmd+Shift+P`
  variant might be more discoverable. Defer to user feedback.
