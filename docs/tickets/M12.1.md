## Cantonese 地道度 — Acceptance criteria

每一條 response 評 3 個 binary 維度，全部 pass 先算「地道」：

### V1. 口語 marker 密度（≥2 個 / 50 chars）

必須至少出現以下 ≥2 個：
- 句末 / 中間：嘅、喎、嘛、咩、啦、㗎、㗎嘛、喺、咁、啦嘛、嘅嘛、嘛喎
- 稱呼：Auntie / 叔叔 / 靚仔 / 靚女
- 英文 mix：OK / sure / no problem / fine / you know / I mean
- 助詞：嘅、咩、㗎、啦、喇、㗎嘛

**失敗**：0-1 marker，整篇睇落似書面語

### V2. 冇書面語句末 / 句式（hard fail）

以下任一出現就 fail：
- 「了」「嗎」「呢」「的」「是」「會」「能」「要」（句末當助詞用）
- 「你好」「請問」「麻煩你」「非常感謝」
- 完整書面語句式：「我認為」「這是」「因為...所以...」
- 普通話詞彙（如果廣東話有對應）：電腦→電腦 OK / 電腦→computer OK，但要避免「軟件」「硬件」「鼠標」→ 滑鼠 / 軟件OK / 文件夾 OK
  - Hard fail 例子：信息、軟件、硬件、鼠標、數據、網絡、文件、互聯網

### V3. 廣東話語序 / 文法（文法啱）

- 比較句「X 過 Y」唔寫「X 比 Y」（廣東話：X 過 Y；普通話：X 比 Y）
- 進行式「而家做緊乜」唔寫「正在做什麼」
- 雙賓語「畀本書我」唔寫「給我一本書」
- 量詞「一隻貓」唔寫「一個貓」
- 「俾我」唔寫「讓我」（俾 = 畀 都 OK）

**失敗**：以上任一中招

## Eval set structure (planned, 25 cases)

每條 case 結構：
```yaml
id: CANT-001
category: casual_chat
input: "你今日做咗啲咩？"
expected_markers: [咗, 啲, 乜]
forbidden_tokens: [了, 什麼, 你今天]
min_marker_count: 2
notes: "簡單日常問答 — baseline 口語度"
```

### Category 分佈

| Category | Count | 目的 |
|---|---|---|
| casual_chat | 6 | 日常閒聊 — baseline |
| tech_help | 5 | 技術問答（用戶最常見） |
| emotional | 4 | 情緒回應（uncle 病咗 / 開心） |
| mixed_lang | 4 | 中英 mix 嘅自然度 |
| edge_case | 3 | 口語 hard case（粗口 / 諷刺 / 反問） |
| instruction_follow | 3 | 跟指令（記低 / 提醒 / 解釋） |

**Total**: 25 cases

### Seed cases（5 條，Ken review 後我再補齊 20 條）

```yaml
- id: CANT-001
  category: casual_chat
  input: "你今日做咗啲咩？"
  must_have_any: [咗, 啲, 乜, 過]
  must_not_have: [了, 什麼, 你今天]
  notes: "最常見閒聊開場"

- id: CANT-002
  category: tech_help
  input: "個 VS Code 起唔到，點算？"
  must_have_any: [個, 唔到, 點算, 喎]
  must_not_have: [了, 怎麼辦, 無法啟動]
  notes: "Tech 問題 — 必須口語化，唔好寫『無法啟動 VS Code』"

- id: CANT-003
  category: emotional
  input: "我 uncle 琴日入咗醫院，好擔心"
  must_have_any: [琴日, 入咗, 好擔心, 嘛, 喎]
  must_not_have: [昨天, 住院, 我很擔心, 請節哀]
  notes: "情緒共鳴 — 必須口語、唔好書面『節哀』"

- id: CANT-004
  category: mixed_lang
  input: "Can you 幫我 check 下個 GitHub PR？"
  must_have_any: [幫我, 嗰, 睇, OK, sure]
  must_not_have: [請幫我, 一下, GitHub, the]
  notes: "中英 mix — 廣東話句式 + 英文 term 自然混入"

- id: CANT-005
  category: edge_case
  input: "你係咪痴線㗎？"
  must_have_any: [係咪, 㗎, 喎, 嘛]
  must_not_have: [你瘋了嗎, 是不是, 傻了]
  notes: "反問 / 粗口 — 唔好答『我不明白您的意思』"
```

## Scorer 設計

`backend/scripts/cantonese_eval.py`（預計 ~150-200 lines）

### Input

- `--set backend/tests/cantonese/eval_set.yaml`
- `--config conf.yaml`（讀現有 LLM config）
- `--out backend/tests/cantonese/results/baseline.json`

### Flow

1. 讀 eval set
2. For each case → call LLM API（用 conf.yaml 嘅 MiniMax config）
3. Apply 3 個 rules：
   - V1: regex `\b(嘅|喎|嘛|咩|啦|㗎|咁)\b` count ≥ 2
   - V2: regex `\b(了|嗎|呢|的|是|請|非常|信息|軟件|硬件)\b` == 0
   - V3: heuristic rules（廣東話特有 pattern check）
4. 計 pass/fail per case
5. 輸出 summary：`{"total": 25, "pass": 12, "pass_rate": 0.48, "v1_fails": [...], ...}`

### 唔做 LLM judge

理由：
- 我哋 judge 自己都可能唔夠地道
- LLM judge 會引入 random noise，難以追蹤 regression
- Rule-based 完全 deterministic，可以入 git diff
