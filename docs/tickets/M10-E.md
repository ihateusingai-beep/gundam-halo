## Context

A5 was the single deferred item from M10-A. Two halves:

1. **Optimistic send** — when the user hits Enter, the message
   should appear immediately with a "pending" visual state. Today,
   the page waits for the network call before showing anything,
   which feels laggy on slow networks. On failure, the bubble
   should flip to an errored state instead of vanishing.
2. **Reload safety** — if the user reloads mid-conversation
   (or deep-links to a project with a session id), the local
   message list should re-hydrate from disk. Today, reload wipes
   the chat and the user has to start over.

The reload-safety half was blocked on a backend endpoint
(GET session messages by session_id alone, no need to know
project_name). That endpoint didn't exist — the only history
endpoint was `/api/projects/{name}/memory/{session_id}` which
requires both the project name AND the session id.

This commit builds:

- **Backend**: `GET /api/sessions/{session_id}/messages` (new)
- **Frontend**: `api.getSessionHistory()` + URL-driven resume +
  optimistic push + error marking on failure
- **Shared**: `lib/message-mapper.ts` (new) — wire-format mapper
  previously inline in B2's SessionDetailPage, now shared between
  B2 (replay) and A5 (live reload)

## What landed (2026-06-12, this session)

### Backend

**File**: `backend/app/api/sessions.py` (+ ~85 lines)

- **New endpoint**: `GET /api/sessions/{session_id}/messages` →
  `SessionHistoryResponse`
- **Schema**: `SessionMessage { role, content, tool_calls, tool_call_id, name }`
  — matches `/api/projects/:name/memory/:session_id` byte-for-byte
  for the `messages` array
- **Source of truth**: always reads from disk
  (`persistence.load_messages`). The in-memory agent is
  intentionally bypassed — disk is at least as up-to-date as the
  agent because every `send_message` call persists the full
  transcript before returning the HTTP response.
- **Project discovery**: prefers the in-memory `_sessions` cache;
  falls back to a disk scan under `~/.gundam-halo/projects/*/`.
  404 only if neither finds the session.
- **Path safety**: `projects_root.exists()` guard before `iterdir()`
  — pre-existing test that bootstraps an empty `tmp_path` would
  crash without it (caught and fixed during this session).

### Code structure — A5 frontend

- **Mount effect** (new `useEffect` keyed on `[id]`) — reads
  `?session=…` from `window.location.search`. If present, calls
  `api.getSessionHistory()` and hydrates the local message list
  via `mapMessages()`. Toasts "Session resumed" on success;
  silent on 404 (stale URL).
- **Optimistic send** — `handleSend` now:
  1. Pushes the user message into `messages` with `pending: true`.
  2. Sends to backend.
  3. On success: replaces the optimistic bubble with a confirmed
     one (no flag), appends the tool-call summary + agent response.
  4. On failure: finds the last pending bubble with matching text
     and flips it to `error: true`. A toast surfaces the cause.
- **URL sync** — when `ensureSession()` creates a new session,
  we `window.history.replaceState` to add `?session=<id>` to the
  URL. Refresh / deep-link now keeps you on the same session.
- **markMessageError(text)** — small helper, 10 lines. Walks
  the messages array backwards, flips the LAST pending bubble
  with matching text to errored. The `text` identifier works
  because we only allow one in-flight send at a time (the
  input is `disabled` while `busy`).

### Code structure — shared mapper

```ts
// frontend/src/lib/message-mapper.ts
export interface BackendMessage { role, content, tool_calls?, tool_call_id?, name? }
export function mapMessages(raw: BackendMessage[]): ChatMessage[]
```

Replaces two copies of the same logic (B2 + A5) with one source
of truth. Pure, no React, no globals — easy to unit test in
isolation if/when we add a Vitest setup.
