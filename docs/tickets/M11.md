## Context

The 2026-06-12 architecture audit surfaced a wide gap between
the README's Mac-control bullet list and the actual codebase:

> "Mac control scope (all confirmed): File I/O, Shell command
> execution, `open <app>`, **AppleScript automation, Clipboard
> management, System notifications, Spotlight / file search,
> Accessibility API (deep)**, `git push` (Mavis sub-agent)"

Of those 9 capabilities, only 3 were actually live: file_read,
file_write, shell_exec (plus `open_app`). The 6 "confirmed"
operations were README vapor. The audit also flagged:

> "**Frontend tests = 0**" — backend has 35 test files / 336 tests.
> Frontend has zero unit tests."

This commit ships both. Two parallel tracks, one commit.

## What landed (2026-06-12, this session)

### Track A — Mac-control surface completion (5 ops)

**New wrappers** (`backend/app/mac/`):

| File | LOC | Wraps | Gating |
|---|---|---|---|
| `apple_script.py` | 64 | `osascript -e <script>` | `cfg.mac.apple_script_enabled` (default True) |
| `clipboard.py` | 75 | `pbpaste` (read) / `pbcopy` (write) | None (single global slot, audit only) |
| `notifications.py` | 92 | `osascript -e 'display notification ...'` | `cfg.mac.notifications_enabled` (default True) |
| `spotlight.py` | 91 | `mdfind <query>` | None (read-only, indexed) |
| `a11y.py` | 174 | `osascript -e 'tell application "System Events" to ...'` | `cfg.mac.a11y_enabled` (default **False**) |

A11y is the only one off by default. The user must opt in to
give the agent Accessibility access. We expose **four read-only**
operations (window_list, app_processes, focused_app, query)
and **deliberately do not** provide synthetic input — that
lives in a higher-trust tool out of v0.1.x scope.

**New tool classes** (`backend/app/tools/`):

| File | Tool name | Wraps |
|---|---|---|
| `apple_script.py` | `apple_script` | `mac/apple_script.py:run_applescript` |
| `clipboard.py` | `clipboard` | `mac/clipboard.py` (read/write) |
| `notify.py` | `notify` | `mac/notifications.py:send_notification` |
| `spotlight.py` | `spotlight` | `mac/spotlight.py:spotlight_search` |
| `a11y.py` | `a11y` | `mac/a11y.py` (4 operations) |

All 5 registered in `tools/builder.py:default_tools()`. Tool
count went 9 → **14** (was 9, +5). All 5 are test-covered.

**Endpoint layer** (`backend/app/api/mac.py`):

5 new POST/GET endpoints:

| Method + path | Body | Returns |
|---|---|---|
| `POST /api/mac/apple-script` | `{script, timeout_sec}` | `{script, exit_code, stdout, stderr, duration_ms}` |
| `GET /api/mac/clipboard` | — | `{text, bytes}` |
| `POST /api/mac/clipboard` | `{text}` | `{bytes, status}` |
| `POST /api/mac/notify` | `{text, title, subtitle}` | `{exit_code, stderr, duration_ms}` |
| `POST /api/mac/spotlight` | `{query, only_in?, max_results?}` | `{query, count, results, exit_code, stderr}` |
| `POST /api/mac/a11y` | `{operation, script?, timeout_sec}` | `{operation, result, items, count, exit_code, stderr, duration_ms}` |

Endpoint count: `/api/mac` 3 → **8** (+5 paths, +1 because
clipboard has both GET and POST).

All audit-logged via the existing `MAC_OP_AUDIT` / `MAC_OP_BLOCKED`
event types — no audit-log changes needed, the dispatcher already
handles these action names. The Tailscale `require_confirm_for`
config list in `SettingsMac` already names `mac.apple_script` and
`mac.a11y` — we just had to ship the implementation that those
flags were waiting for.

### Why a small start (not "test everything")

The floor-first approach: pick the highest-leverage pure helpers
and the most-reused component. 5 files / 47 cases covers:

- The contract between frontend and backend (message-mapper)
- The most-reused visual component (MessageBubble)
- The format helpers used by 3 routes
- The className combiner used by every cockpit component
- The relative-time formatter used by 3 cards

If someone re-styles `MessageBubble` or breaks the wire-format
mapper, the test catches it. The next sprint can grow from here
(component tests for HudCard, ToolCallTrace, MissionCard, etc.).

### Live wire-test (real backend, port 18769)

Booted a real backend, hit the new endpoints, got:

- `POST /api/mac/apple-script {script: 'return "hello from as"'}`
  → `200`, `stdout: "hello from as"`, `exit_code: 0`, 57ms
- `GET /api/mac/clipboard` → `200`, returns the current
  clipboard text (132 bytes — confirmed pbcopy is on this Mac)
- `POST /api/mac/notify {text: "test"}` → `200`, `exit_code: 0`,
  82ms (`osascript display notification` actually fired)
- `POST /api/mac/spotlight {query: "kind:folder", max_results: 3}`
  → `200`, 3 real directory paths returned
- `POST /api/mac/a11y {operation: "windows"}` → `403`
  (a11y_enabled = false, as designed)

The AppleScript and Notification calls actually executed on the
Mac during the test — not mocks, real `osascript`. The 403 on
A11y is correct because the user has not opted in.
