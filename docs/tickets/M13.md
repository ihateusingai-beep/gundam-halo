## Context

Today, bringing up Gundam Halo from scratch looks like:

```bash
git clone https://github.com/ihateusingai-beep/gundam-halo
cd gundam-halo
./install.sh                          # copies config.toml.example
uv run run_server.py                   # BOOM: "MINIMAX_API_KEY not set"
# user googles → edits ~/.gundam-halo/config.toml by hand
# restart → "Voice backend X not configured"
# user pings Ken on Telegram: "點 enable voice"
# 5-10 minutes of friction before first "hello"
```

This is fine for Ken (the dev), but for **anyone else** — friends,
beta testers, future customers — it's a 10-minute wall. The
product promise of "offline-first AI companion" doesn't survive
the first 5 minutes.

M13 adds a **first-run wizard** that:

1. Detects "no config / missing required fields / backend can't
   start" state
2. Walks the user through the 7 critical setup steps
3. Writes a valid `~/.gundam-halo/config.toml` at the end
4. Tests the LLM connection (and one voice round-trip if voice
   is enabled)
5. Hands off to the main dashboard

The wizard lives at `/setup` in the web dashboard and as the
default landing screen in the Tauri desktop app. Skipping is
possible (advanced users) but discouraged.

## 7-step flow

| # | Step | Inputs | Validation | Writes to TOML |
|---|---|---|---|---|
| 1 | **Welcome** | (none) | n/a | n/a |
| 2 | **LLM provider** | provider (`minimax`/`openai`/`ollama`/`anthropic`), API key, base URL, model | test_connection → 200 | `[llm]` |
| 3 | **Voice ASR** | backend (`whisper_local` / `sherpa`), model size, language | model dir exists or downloadable | `[voice.asr]` |
| 4 | **Voice TTS** | backend (`edge` / `openai` / `cosyvoice`), voice, rate | n/a (test happens later) | `[voice.tts]` |
| 5 | **Theme** | pick 1 of 8 themes (NT-D / GOD / Unicorn / etc.) | n/a | `[user].default_theme` |
| 6 | **Tailscale** | hostname (default `gundam-halo`), confirm reachable | `tailscale ping` from this Mac | `[server]` |
| 7 | **Smoke test** | (none — backend runs end-to-end) | text chat round-trip + (optional) voice round-trip | n/a |

State persisted in `~/.gundam-halo/setup_state.json`:
```json
{
  "version": 1,
  "current_step": 3,
  "completed_steps": [1, 2],
  "started_at": "2026-06-13T14:00:00Z",
  "finished_at": null,
  "skipped": false
}
```

`finished_at` set + `config.toml` exists + all required fields
populated → wizard hides itself, user lands on `/`.

## Detection logic — `GET /api/setup/state`

```python
def compute_setup_state(home: Path) -> SetupState:
    cfg_path = home / "config.toml"
    if not cfg_path.exists():
        return SetupState(status="needs_setup", step=1,
                          reason="no config.toml")
    cfg = load_config(home)
    missing = []
    if not cfg.llm.api_key and not os.getenv(cfg.llm.api_key_env):
        missing.append("llm.api_key")
    if cfg.voice.enabled and not cfg.voice.asr.model_path:
        # only if user opted into voice
        missing.append("voice.asr.model_path")
    if cfg.server.require_tailscale:
        if not is_tailscale_reachable():
            missing.append("server.tailscale")
    if missing:
        return SetupState(status="needs_setup", step=step_for(missing[0]),
                          reason=f"missing: {missing}")
    return SetupState(status="ready")
```

**Frontend**:
```ts
// At app boot
const state = await api.getSetupState();
if (state.status === "needs_setup") {
  return <Navigate to={`/setup?step=${state.step}`} replace />;
}
```

## API design

```
GET  /api/setup/state                 — current state
POST /api/setup/start                 — begin wizard, set started_at
POST /api/setup/llm                   — save LLM config, test connection
POST /api/setup/voice-asr             — save ASR config, validate model
POST /api/setup/voice-tts             — save TTS config
POST /api/setup/theme                 — save theme pick
POST /api/setup/tailscale             — save hostname, test reachability
POST /api/setup/smoke                 — run end-to-end smoke, return result
POST /api/setup/finish                — mark finished, redirect target=/

POST /api/setup/skip                  — mark skipped (advanced)
POST /api/setup/reset                 — wipe state, restart at step 1
```

Each `POST` returns `{ok, next_step, errors?}`. `errors` is a
list of `{field, code, message}` so the UI can highlight fields.

## Frontend design

### Route structure

```
/setup               — wizard root (no params = auto-redirect to ?step=N)
/setup?step=1        — welcome
/setup?step=2        — LLM
...
/setup?step=7        — smoke test
/setup?done=1        — success screen (auto-redirects to /)
```

### Component tree

```
<SetupLayout>                        — full-bleed, hides cockpit chrome
  <SetupProgress>                    — top bar, 7 dots
  <SetupStepContainer>               — wraps active step
    {step === 1 && <WelcomeStep />}
    {step === 2 && <LLMStep />}
    {step === 3 && <VoiceASRStep />}
    {step === 4 && <VoiceTTSStep />}
    {step === 5 && <ThemeStep />}
    {step === 6 && <TailscaleStep />}
    {step === 7 && <SmokeStep />}
  <SetupNav>                         — back / next / skip
</SetupLayout>
```

### Key UX rules

- **One step per screen** — no scrolling
- **Validation inline** — submit button disabled until valid
- **No back-button trap** — back always works
- **Skip button visible** at every step (advanced users)
- **Test connection** button on LLM step (not just save)
- **Smoke step** is the only step with no Next button — it
  auto-advances to `?done=1` on success

### Tauri vs Web

- **Web dashboard** (this ticket) — `/setup` route, served by FastAPI
- **Tauri 2 app** (future) — opens to `/setup` on first run; same
  wizard content; different chrome (no browser back button)

## Backend TOML write strategy

Two options:

### Option A — write through the live `Config` dataclass
```python
def save_step_llm(payload: LLMSetupPayload, home: Path) -> None:
    cfg_path = home / "config.toml"
    cfg = load_config(home)
    cfg.llm.provider = payload.provider
    cfg.llm.api_key_env = payload.api_key_env
    cfg.llm.base_url = payload.base_url
    cfg.llm.default_model = payload.default_model
    # write back as TOML
    write_toml(cfg, cfg_path)
```

### Option B — string-template the TOML
Less safe, harder to preserve comments.

**Pick**: A. Use the dataclass as the source of truth, dump via
`tomli_w`. (Config already loaded via `tomllib`; need to add
`tomli_w` to pyproject or use stdlib `tomllib` round-trip.)

**Security**:
- `api_key_env` is the only LLM secret field written; **NEVER**
  write the raw key to TOML
- `secrets_store` (existing) holds raw keys; wizard writes the
  env-var name reference only
- API key received from wizard → store in secrets_store →
  return env var name → write `api_key_env = "..."` to TOML

## Implementation impact (refined)

### 7-step flow (locked)

| # | Step | Required? | Skip 寫乜 | Validate |
|---|---|---|---|---|
| 1 | Welcome | optional | nothing | n/a |
| 2 | LLM | **required** | skip 後 dashboard 永遠提示 missing | test_connection → 200 |
| 3 | Voice ASR | **required** (per Q3) | n/a — cannot skip | model dir exists or auto-download |
| 4 | Voice TTS | **required** (per Q3) | n/a — cannot skip | n/a (test later) |
| 5 | Theme | optional | default NT-D | n/a |
| 6 | Tailscale | optional | defer + show install link | `tailscale ping` reachable |
| 7 | Smoke | required to finish | n/a | text + voice round-trip |

### Required vs optional 區分

Steps 2/3/4/7 = required. Steps 1/5/6 = optional. "Finish" blocked
until 2/3/4 至少有值，step 7 pass。

### TOML writes

- Step 2: `[llm]` section + `secrets_store` 寫 raw key
- Step 3: `[voice.asr]` + `[voice].enabled = true`
- Step 4: `[voice.tts]`
- Step 5: `[user].default_theme`
- Step 6: `[server].tailscale_hostname`, `[server].require_tailscale = true`

### `secrets_store` contract

Wizard 收到 raw key:
```
POST /api/setup/llm
{ "provider": "minimax", "api_key": "sk-xxxxx", "base_url": "...", "default_model": "MiniMax-M3" }
```
Backend flow:
1. Validate key via test_connection to LLM provider
2. On success, write raw key to `secrets_store` with name `minimax_api_key`
3. Write `[llm].api_key_env = "MINIMAX_API_KEY"` to TOML
4. Return `{ok, next_step: 3, stored_env: "MINIMAX_API_KEY"}`

Frontend 唔再 hold 個 raw key，response 已經係 env name only.

### Reset wizard

Settings → "Reset wizard" button:
- Wipe `setup_state.json`
- Keep `config.toml` intact (advanced users)
- Set `setup_state.current_step = 1`, `completed_steps = []`
- Next launch → auto-redirect `/setup`

UX: button 旁邊 warn text 「你的 config.toml 會保留。但 wizard 會從頭跑過。」
