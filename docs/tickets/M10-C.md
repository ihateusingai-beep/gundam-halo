## Context

B6 (the global ⌘K command palette) landed first as the "demo 最 wow"
anchor. B2 was the natural next item because it consumes the
`MessageBubble` component that A8 extracted — A8's documentation
explicitly flagged B2 as the second caller, so shipping B2 closes
that refactor's promise and proves the component is reusable outside
the live chat surface.

The old `ProjectMemoryPage` already had a "click session → expand
inline" UX (`ExpandedSession`), but it used a hand-rolled mini-bubble
inside `gundam-memory-msg-*` CSS classes, and the expand logic was
locked in a side-effecting `useState<Record<string, ExpandedMessages>>`
that re-fetched on every click. B2 lifts that into a proper page.

### Code structure (B2 page)

- **`SessionDetailPage`** — main component. Pure function. Local state
  for messages / loading / error / metadata. `useEffect` on `[id, sessionId]`.
- **`mapMessages()`** — pure, isolated wire-format → UI-shape conversion.
  Easy to unit test. Falls back to `(no result)` for tool messages with
  empty content, and to empty string for assistant messages with only
  tool calls.
- **`Stat`** — small presentational component for the metadata bar.
  3-line render, no logic.
- **`Header`** — separate so loading / error states can still show
  the breadcrumb back link.
- **`formatDateTime`** — local helper (mirrors `formatTime` in memory.tsx
  but with month name). 12 lines, pure.

### A8 payoff realized

`MessageBubble` is now used in **two** call sites:

1. `ProjectDetailPage` — live chat during an active session (A8's original consumer)
2. `SessionDetailPage` — replay of a persisted session (B2, this commit)

Same component, same role mapping, same styling. The `assistant → agent`
rename lives in **one** place (`mapMessages` for the historical wire
format). If we ever change how tool calls render (e.g. collapse
adjacent tool traces, syntax-highlight JSON args), the change lands
in one file and benefits both surfaces.
