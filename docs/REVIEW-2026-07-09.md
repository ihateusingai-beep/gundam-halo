## 1. Wizard / setup — **B+**

**Files**: `components/wizard/{WizardShell, StepWelcome, StepLLM, StepVoiceASR, StepVoiceTTS, StepTheme, StepTailscale, StepSmoke, StepFinish}.tsx` (~1500 LoC total)
**Tests**: 4 step tests (StepLLM / StepVoiceTTS / StepSmoke / StepTheme) — missing StepVoiceASR / StepTailscale / StepFinish / StepWelcome
**Hook**: `hooks/useSetupWizard.ts`

### Strengths
- 7-step linear flow with `WizardShell` purely presentational (state lives in `useSetupWizard`)
- Per-step `onChange({...})` shape that's composable + testable
- Persistence via the backend (`/api/setup/state`) survives reload

### Gaps

| # | Gap | Severity |
| - | --- | -------- |
| W1 | No test for StepVoiceASR / StepTailscale / StepFinish / StepWelcome — 4 of 9 steps uncovered | High |
| W2 | `WizardShell` 253 LoC is borderline; could be split into `<StepIndicator>` + `<StepNav>` (was Sprint 50 standing rule) | Medium |
| W3 | No "skip" affordance for optional steps (Tailscale is optional but treated as required) | Medium |
| W4 | StepTheme / StepLLM hard-code the user-visible form state; no schema validation (Zod) | Medium |
| W5 | No e2e test — the smoke test step (StepSmoke) only checks backend reachability, not end-to-end TTS→ASR→reply | Low |

### Additions

- **W-A1: Per-step unit tests for the 4 uncovered steps** (Sprint 60 — 2-3h)
- **W-A2: Schema validation via Zod** for the form payload (Sprint 60 — catches typos before backend round-trip)
- **W-A3: Skip-to-end option** for users who already have everything configured; show a banner "Skip to verify" after step 1
- **W-A4: Wizard re-entry banner** when a returning user lands on `/setup` mid-flow with state from a prior session ("You were at step 5 — resume?")

### Removals / consolidations

- **W-R1: Drop `StepFinish` standalone component if it's <30 LoC** — could collapse into WizardShell's success state (cleaner tree)
- **W-R2: Drop the legacy "Restart wizard" button** in StepSmoke — it bypasses the persisted state machine, which is a footgun

## 2. Avatar / EQ cockpit — **B+**

**Files**:
- Avatar: `components/live2d/{CSSAvatar, ImageSetAvatar, AvatarCard}.tsx` (~686 LoC)
- EQ: `components/gundam/{VoicePanel, EqVisualizer, CockpitEqCard}.tsx` + `lib/{audio-eq, audio-graph}.ts` (~1400 LoC)
**Tests**: 7+4+3+4+3+5 = 26 tests across the EQ + avatar scope (Sprint 57-59)

### Strengths
- **Per-theme TTS EQ** (Sprint 57) — 8 themes × 5-band BiquadFilter, snap (no ramp) matching visual theme switch
- **Live avatar emotion sets** (Sprint 58-59) — full 9-emotion × 9 themes coverage
- **PER_THEME_EXT** extension table handles matrix MCP's random JPEG/PNG output (Sprint 59)
- TtsAudioGraph has clean dispose path → no AudioContext leak on hot-reload

### Gaps

| # | Gap | Severity |
| - | --- | -------- |
| A1 | `VoicePanel.tsx` 548 LoC — borderline; could split out TTS playback queue logic (lines 145-300) into `lib/tts-player.ts` | High |
| A2 | `ImageSetAvatar` + `CSSAvatar` both exist; `AvatarCard` switches between them but the choice is stored in localStorage without per-theme defaults | Medium |
| A3 | No EQ preset preview UI — users see the visualizer react but can't A/B compare two themes | Medium |
| A4 | `audio-eq.ts` PER_THEME_EXT-style maps have hard-coded numbers per theme; no test pinning the exact EQ values | Low |
| A5 | No accessibility: visualizer is decorative; screen reader users get no equivalent info (e.g. "now playing at +3dB") | Low |

### Additions

- **A-A1: Extract TTS playback queue into `lib/tts-player.ts`** (~150 LoC out of VoicePanel) — Sprint 60, makes VoicePanel easier to test
- **A-A2: Per-USER EQ independent of theme** (deferred from Sprint 57) — lift the EQ preset registry into a `useEqStore` (mirroring `useThemeStore`)
- **A-A3: "A/B compare themes" button** in the EQ card — temporarily applies a second theme's preset for 10s, then reverts. Lets the user hear the difference without committing.
- **A-A4: EQ preset snapshot test** pinning the exact dB values per theme per band — catches accidental drift in `audio-eq.ts`
- **A-A5: a11y visualizer** — emit a `aria-label` like "Bass +4dB · Mid 0dB · Treble -2dB · LIVE" updated per render

### Removals

- **A-R1: Drop `ImageSetAvatar` image-preload effect** if it's redundant — current behavior preloads 9 PNGs on mount which is 8 wasted requests when the user only sees 1
- **A-R2: Drop `cockpit-bg.test.ts`** (or merge into `cockpit-bg.test.ts` → `cockpitLayout.test.ts`) — it's currently a one-off stub that doesn't actually render the component

## 3. UI primitives — **A-**

**Files**: `components/ui/{button, command, dialog, dropdown-menu, input-group, input, textarea}.tsx` (~1100 LoC)
**Tests**: 0 — none of the UI primitives have tests

### Strengths
- All primitives wrap `@base-ui/react/*` or `cmdk` — no hand-rolled a11y, gets the upstream ARIA for free
- CVA-based variants (button.tsx) — composable, type-safe, no copy-paste
- `cn()` helper + `data-slot="..."` pattern → consistent DOM introspection
- Tied to design tokens via `bg-popover`, `text-muted-foreground`, etc. → themed per gundam.css

### Gaps

| # | Gap | Severity |
| - | --- | -------- |
| U1 | **0 tests** — Sprint 50 deferred-list noted this; never re-prioritised | High |
| U2 | `input-group.tsx` has 3 internal variants (button / tooltip / text addon) with no per-variant docs | Low |
| U3 | No `Card` primitive — every HudCard is a hand-rolled CSS class in gundam/ | Low |
| U4 | `dropdown-menu.tsx` 266 LoC — has 12 sub-components; some duplicate the dialog.tsx API | Low |

### Additions

- **U-A1: Smoke tests** for the 7 UI primitives (render + snapshot variant props). Sprint 60, 1h.
- **U-A2: Extract `Card` primitive** from `HudCard` — would let non-cockpit routes (e.g. `/setup`, `/audit`) use a consistent card without the gundam-specific chrome
- **U-A3: A11y test** for Dialog (focus trap, Escape close, restore-focus) using `@testing-library/user-event`

### Removals

- **U-R1: None** — primitives are all in use; the value is having them centralised
- **U-R2: Possibly consolidate `dropdown-menu.tsx` 12 sub-components** if any are unused — quick `grep` audit

| S2 | SecretsTab 282 LoC is borderline (no per-section split yet) | Medium |
| S3 | MemoryTab 224 LoC has user-memory CRUD with no schema validation | Medium |
| S4 | No "discard changes" affordance on any tab — user can lose edits on navigation | Medium |
| S5 | Per-tab loading state is inconsistent (some show "Saving…", some don't) | Low |

- **S-A4: Save-bar shared component** (extracted from VoiceTab's `SaveBar`) — single source of truth for the "Save / Reset / Saving…" affordance
- **S-A5: "Last saved at 14:32" timestamp** under each tab title

- **S-R1: Drop ChannelsTab** if Telegram gateway isn't actively used by the user (per profile memory: Telegram was architected as a phone fallback but isn't actively used in 2026-06). Audit before removal — the user might still want it for future use.
