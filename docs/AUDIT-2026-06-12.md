## 4. Honest assessment

**Strong**:
- Real working voice + Live2D + tray stack — M1/M2/M3/M4 fully delivered
- Mac-control primitives that *are* there (file I/O, shell, open_app) are policy-gated, audit-logged, and tested
- Per-project isolation is real (not aspirational)
- Frontend polish is now solid after M10 (B6/B2/B7/A5)
- Backend test coverage is real (35 files, 336 tests)

**Honest gaps**:
- README advertises 6 Mac-control capabilities that don't exist
- The "Tailscale-only" security claim is half-implemented
- "Signal channel" is in the README and ARCHITECTURE but no code
- No SQLite/FAISS for memory — only structured KV
- Only 1/8 themes have a real Live2D motion map
- 0 frontend tests

**Recommended next 3 priorities** (if user wants a v0.1.x → v0.2 push):

1. **Tailscale auth middleware** — actually enforce `require_tailscale` and ship `auth.py`. Closes a real security claim, unblocks remote phone use. ~half day of work.
2. **Either implement the 6 README-claimed Mac ops or remove them from README** — pick one. Implementation is more honest, but cleanup is faster. Recommend removal for v0.1.x, schedule for v0.2.
3. **Frontend test setup** — Vitest, 10-15 tests on the pure helpers (mapMessages, groupByDate, formatRelative, formatTime). ~half day. Sets the floor for future test growth.

Stretch priorities (v0.2+):
4. Live2D responders for the other 7 themes (per-theme emotion DSL → motion map)
5. SQLite + embeddings for semantic memory recall
6. Cantonese fine-tune v0.1.3 → 0.1.4 (run the training, validate against base)
7. MavisBridge end-to-end live test in a real session
8. Signal channel (if user actually wants it; Telegram covers 90% of phone use)
9. First-run wizard (`gundam-halo init`)
10. `gundam-halo doctor` self-check
